cookie-sentinel

Audit the cookies your site sets before attackers do.

Fetches your pages, follows every redirect, collects every Set-Cookie header from every hop and audits each cookie against modern browser rules and security best practice, with a concrete fix for every finding. Classifies cookies offline against a bundled Open Cookie Database snapshot. Also audits raw Set-Cookie lines from a file or stdin. Zero runtime dependencies.

$ npm i -D cookie-sentinel
Read the docs View on npm Source on GitHub

01 The problem

A session cookie without HttpOnly, a SameSite=None cookie without Secure, a Domain= that hands your auth cookie to every subdomain: these slip in through framework defaults, middleware and third-party code, and they are invisible in the UI.

cookie-sentinel collects every Set-Cookie from every redirect hop, logged-in pages included, and fails CI with the exact attribute to add.

02 Features

01

Every hop audited

Follows redirects and audits cookies set by each response, including plain http:// hops.

02

Modern browser rules

Secure, HttpOnly, SameSite, __Host- / __Secure- prefixes, Partitioned, Domain and Path scoping.

03

Sensitive values

Flags JWTs in cookies, unsigned alg:none JWTs and email addresses (plain, URL-encoded, base64 or in JWT claims).

04

Cookie tossing

Detects duplicate cookies and one name set with different Domain/Path scopes.

05

Open Cookie Database

Offline classification: first vs third party, tracking vs essential, vendor and category.

06

Logged-in pages

Headers, bearer tokens, cookie jars, scripted login and same-origin crawling.

07

JS-set cookies

Optional Playwright or Puppeteer peer dependency to capture cookies set by scripts.

08

Offline mode

Pipe raw Set-Cookie lines in with --input; text, JSON, SARIF and Markdown output.

03 Usage

# Audit a site

$ npx cookie-sentinel https://example.com

# Extra paths, stricter gate

$ npx cookie-sentinel https://example.com -p /login -p /account --fail-on medium

# Crawl same-origin links

$ npx cookie-sentinel https://app.example.com --crawl-depth 2 --max-pages 40

# Offline to SARIF

$ npx cookie-sentinel --input set-cookies.txt --origin https://app.example.com -f sarif > cookies.sarif

04 CI / GitHub Action

permissions:
  contents: read
  security-events: write
jobs:
  cookies:
    runs-on: ubuntu-latest
    steps:
      - uses: MrLouisWright/cookie-sentinel@<sha>
        with:
          urls: https://staging.example.com
          paths: /login /account
          bearer: ${{ secrets.STAGING_TOKEN }}
          fail-on: medium
          args: --crawl-depth 1 --max-pages 20
          sarif: cookies.sarif

05 Options & flags

FlagDescription
<url…>URLs to fetch (https:// assumed). Redirects are followed and cookies from every hop are audited
-p, --path <path>Extra path to fetch on every URL (repeatable)
--crawl <file>File of URLs or paths, one per line
--crawl-depth <n>Follow same-origin links up to depth n (0 = off)
--max-pages <n>Cap when crawling (default 25)
-H, --header "Name: value"Request header (repeatable), e.g. Cookie or Authorization
--headers-file <file>JSON headers for scripted auth
--cookies-file <file>Cookie jar file (JSON, name=value lines, or Netscape format)
--bearer <token>Authorization: Bearer shortcut (or COOKIE_SENTINEL_BEARER)
--browser <engine>playwright or puppeteer (optional peer dependencies)
-i, --input <file|->Audit raw Set-Cookie lines offline
--origin <url>URL context for --input (default https://example.com/)
-c, --config <file>JSON config (default .cookie-sentinel.json if present)
-f, --formattext (default), json, sarif, markdown
--fail-on <sev>critical, high (default), medium, low, info or none
--no-classifySkip Open Cookie Database enrichment
